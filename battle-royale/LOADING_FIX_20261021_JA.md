# ロード停止修正（2026-10-21）

## 確認できた原因

現行ローカルHTMLは head/body の開始・終了タグを省略した形式だった。前回の更新で `<body>` と `</head>` を置換対象にしたため、ロード画面の6要素も update-ui.css のリンクも挿入されていなかった。一方で起動コードは loadingScreen.hidden を操作するため、存在しない要素にアクセスして起動が止まる構造になっていた。

以前のDOM代替テストは存在しないIDにもオブジェクトを生成していたため、この欠陥を見逃した。以前の検査合格は実ユーザーの起動成功を証明していなかった。

## 修正

- head/bodyを明示し、実HTMLにロード画面6要素とCSSリンクを配置。
- CSSとasset-loader.jsの参照にローカル更新用の版指定を追加。公開先のキャッシュ状態は未調査。
- 必須画像の失敗・タイムアウトでは対象パスを表示し、再試行を提供。失敗状態でreadyを真にしない。
- asset-loader.js自体の読み込み失敗でもエラーと再読み込みボタンを表示。
- 既存の読み込み削減、3体編成、ボタン配置、戦闘仕様、原画、セーブ処理は保持。

## 検証

新設 tests/battle-royale-startup.test.cjs は実HTMLからIDを取得し、存在しないIDを代替生成しない。修正前ファイルでは loadingScreen が0件で失敗し、修正後は以下に合格。

- 実HTMLの必須6要素、CSS参照、ローダーの実行前配置。
- 起動成功／必須画像失敗／無応答タイムアウト／再試行成功。失敗中はready=falseのまま。
- 失敗パスの表示、成功した画像のキャッシュ再利用、ローダーJS取得失敗のエラー表示。
- ネイティブCanvasで起動必須44画像をすべて実デコード。
- 既存の静的検査（28スクリプト・2,824素材参照・相対パス）、編成・出撃フロー、40通りの空中強攻撃、アサモブ必殺、遠距離CT0、ローダー検査。
- git diff --check 合格。

これはNode VM・DOM代替・ネイティブ画像デコードによる検査。Chrome、ブラウザ自動操作、iPhone、実ネットワークでのユーザー起動は未検証。ユーザーが開いた具体的なURL／ファイルおよび公開先のファイル一致も未確認。ローカルで確認できた原因を修正したもので、公開版への反映はしていない。
